## v0.313 changes

- Photo-equipped **local and shared markers** are **48×48 px** instead of 64×64 px (25% smaller per side); their border stays 5 px and their center anchors remain aligned to coordinates. The add-marker photo preview is also 48×48 px. Player photos remain 32×32 px; markers with no photo stay diamonds. Already shared thumbnail data works unchanged—only rendering size changes.
- Default Chronicle story-generation interval is **5 minutes** on open developer-mode clients (previously 1 minute). Overseer Display's automatic overview refresh—player list and Chronicle—also changes from 30 seconds to **5 minutes**, with a `5:00` countdown. The Chronicle frequency selector now starts on **5m**, retains other choices and manual ↻ REFRESH. Firebase listeners can still display new Chronicle entries as they arrive; the change affects periodic generation/overview refresh, not live listener delivery. No server-side scheduler is involved.

## v0.312 corrections

- From **OVERSEER DISPLAY**, **+ MARKER** now explicitly captures the center-dot map position. **SAVE MARKER** writes only the waypoint storage key (not the unrelated player profile/inventory), redraws the map, and then asks **SHARE WITH EVERYONE?** separately. A blank/overlong name, unavailable map position, or full/unavailable device storage shows an **inline error in the marker editor** instead of an invisible notification behind it. After saving, a status line above the Overseer map explicitly reports **saved locally**, **shared successfully**, or **broadcast failed**; a Firebase share failure does not erase the local marker. Failed storage creates no phantom local marker and never offers global sharing. The MAP-tab marker flow uses the same safe save path.
- Shared/global map tooltips show the **marker name only**, without `— VIA PERSON`. After you **select** a shared marker on the map, its card still identifies **SHARED BY PERSON** and shows its distance and Overseer removal action.
- Do not interpret a private local save as a global marker: press **SHARE WITH EVERYONE** in the separate confirmation and check the broadcast on another device. Photo-bearing shared pins still need the updated rules from v0.311; an older set of rules rejects the `photoThumb` field.

## v0.311 features included in this full package

- Synthetic demo-player creation and timestamp refresh have been removed. Map and Overseer roster show only genuine beacons seen in the last five minutes; old demo records are suppressed even before cleanup. Old Chronicle history is retained.
- A live **Overseer-mode client** generates Chronicle gathering stories from current beacons. Five through nine real, non-scrambled users within **15 metres pairwise** get one of **20** small-group variants; **ten or more** get one of **20** large-group variants (exactly 10 uses the large tier). Scrambler ON or legacy beacons without an explicit `scrambled:false` are *not* treated as reliable physical positions. Multiple Overseer devices use a transaction and a 15-minute event window to avoid duplicate writes for the same group anchor. Like other client-side features, generation only runs while an Overseer app is open/connected; there is no background server scheduler.
- In **OVERSEER DISPLAY**, tap a local or shared marker on the **map** to reveal **REMOVE SELECTED LOCAL/SHARED MARKER**. This Overseer control is hidden until a marker is selected. Removing a local marker affects only that device. Removing a shared marker asks for confirmation and deletes the broadcast for everyone; it does not delete a corresponding private local marker. Existing ordinary MAP-tab local marker controls remain.
- When adding a marker, **OPTIONAL PHOTO FROM DATABANK** selects an existing app photobank image (or first take one in the app). A small square-cropped JPEG thumbnail appears on the marker, approximately **48×48 px**, with a **5 px border**, versus a **32×32 px** photo-equipped player beacon. Choose **REMOVE SELECTED PHOTO** to revert to a diamond. Saving keeps the marker local first and separately asks **SHARE WITH EVERYONE?**; only a confirmed broadcast carries its thumbnail to other devices. Without a photo, existing diamond markers remain. Existing shared pins remain compatible.
