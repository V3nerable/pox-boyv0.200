**Prepared release; NOT deployed.** This ZIP contains `pwa/` only. The live GitHub Pages site, Firebase rules and existing Firebase data have **not** been changed here. No Firebase Functions deployment is required.

This adds the optional `wastelanders/$uid/scrambled` boolean and optional `sharedpins/$pinId/photoThumb` JPEG data-URI validation (maximum 25,000 characters). Earlier v0.309 planner/WIRE rules are included. Do this **before** uploading the new website files. Publishing rules is not secure Overseer authorization: this app deliberately retains its existing UI-only developer gate.
2. Upload the **contents** of `pwa/` directly into the GitHub Pages repository **root**, not the enclosing `pwa/` folder. Preserve pre-existing live media/favicons; the ZIP does not include them. The service worker cache is `pipboy-cache-v293`; it no longer fails installation if optional audio, favicon or Google Fonts are unavailable. Confirm the site shows `v0.311` on all devices after refresh.
3. In an Overseer unit after checking the download folder is accessible, open **OVERSEER DISPLAY → BACK UP & REMOVE DEMO PLAYERS**, choose **DOWNLOAD JSON BACKUP**, confirm the file actually arrived in Downloads, then (only if it did) click **YES, I HAVE THE BACKUP — REMOVE DEMO PLAYERS**. Removal is not attempted before that second confirmation. This operation targets **only** `wastelanders/demo-player-1` through `demo-player-10` when the record still has `isDemo: true`; removal is conditional on that flag at write time. It does not remove real players, other test records or old Chronicle stories. **This cleanup has NOT been executed.** If the download fails, choose **NO / CANCEL**; check the backup exists before confirming deletion. Firebase deletion cannot be undone without a backup.
4. Test on two real devices with the actual rules and a live network; this has not been done by the agent.

## Changes

- Synthetic demo-player creation and timestamp refresh have been removed. Map and Overseer roster show only genuine beacons seen in the last five minutes; old demo records are suppressed even before cleanup. Old Chronicle history is retained.
- A live **Overseer-mode client** generates Chronicle gathering stories from current beacons. Five through nine real, non-scrambled users within **15 metres pairwise** get one of **20** small-group variants; **ten or more** get one of **20** large-group variants (exactly 10 uses the large tier). Scrambler ON or legacy beacons without an explicit `scrambled:false` are *not* treated as reliable physical positions. Multiple Overseer devices use a transaction and a 15-minute event window to avoid duplicate writes for the same group anchor. Like other client-side features, generation only runs while an Overseer app is open/connected; there is no background server scheduler.
- In **OVERSEER DISPLAY**, tap a local or shared marker on the **map** to reveal **REMOVE SELECTED LOCAL/SHARED MARKER**. This Overseer control is hidden until a marker is selected. Removing a local marker affects only that device. Removing a shared marker asks for confirmation and deletes the broadcast for everyone; it does not delete a corresponding private local marker. Existing ordinary MAP-tab local marker controls remain.
- When adding a marker, **OPTIONAL PHOTO FROM DATABANK** selects an existing app photobank image (or first take one in the app). A small square-cropped JPEG thumbnail appears on the marker, approximately **64×64 px**, with a **5 px border**, versus a **32×32 px** photo-equipped player beacon. Choose **REMOVE SELECTED PHOTO** to revert to a diamond. Saving keeps the marker local first and separately asks **SHARE WITH EVERYONE?**; only a confirmed broadcast carries its thumbnail to other devices. Without a photo, existing diamond markers remain. Existing shared pins remain compatible.
